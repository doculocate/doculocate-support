Understand the app

Privacy & storage

Where documents are processed, how long they remain, and current access limits.

Checked against the app · September 27, 2026

On this page

Where processing happens

Uploaded documents are sent to the DocuLocate application server for text extraction and search. A local installation processes them on the machine running that server. Accessing an instance through a browser does not make its processing browser-only.

What the application retains

The current document store keeps original file bytes, extracted text, metadata, and cached search data in server memory. Removing a document, collection-capacity eviction, or restarting the process clears that document from this store. There is no persistent document database in the current implementation.

This describes application storage, not operating-system behavior, infrastructure logs, backups, or external provider retention. The application enables request logging; do not assume all metadata is absent from logs.

When text goes to an external provider

Base semantic retrieval runs on the application server. With optional AI reranking enabled, queries and candidate passages are sent to the configured provider. Review its policies before using sensitive material. No blanket claim is made about provider training or retention.

Accounts and access

The current workspace is shared

There are no user accounts, authentication, or isolated user workspaces. Anyone able to access the current instance may be able to list, search, retrieve, and remove documents in its store.

The server currently defaults to HOST=0.0.0.0. For use only on your own machine, explicitly bind it to 127.0.0.1. Network access controls must be supplied by the deployment environment.

Sharing information with support

Use a small, synthetic example when reporting a problem. Do not post confidential documents, API keys, private URLs, or raw production logs in public issues. See reporting an issue for a checklist.
